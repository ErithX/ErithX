# Project Rules for Contest Tracker

## Architecture Documentation
- Whenever we implement a major architectural decision, complex logic, or solve a difficult trade-off (a "critical task"), you MUST automatically document the decision, rationale, and implementation details in `challengs.txt` located at the root of the project.
- Do this proactively. Do not wait for the user to ask you to record it.

## Task Tracking
- Always use the `task.md` file in the root of the workspace (`e:\projects\contest-tracker\task.md`) to track remaining jobs and record remaining tasks. This file is the source of truth for the backlog.
